# Sheliak — ノート層仕様 (phrase / loop / 操作セット)

> format_version: 0.1
> このファイルは **ノート記述層** の仕様。音源側 (Patch IR / WASM ABI / パラメータレイアウト) は
> `docs/SPEC.md` を参照。現行実装の `loop` フェンス (音符をインラインで持つ形式) は本仕様で置き換える。

---

## 1. 位置づけ

現行のノート層は `loop` フェンスに全トラックの音符をインラインで持っている。

```
lead: [C4 Eb4 G4] ~ ~ ~ | ~ ~ ~ ~ | ...
bass: .  .  C2 .        | ...
```

これは「音が出るか」を検証するには十分だったが、次の3点を満たせない。

1. **音の高低が見えない** — 音名の羅列なので輪郭が読めない
2. **フレーズを再利用できない** — 同じフレーズを複数箇所から参照できず、コピペになる
3. **表情を書く場所がない** — ベロシティ・タイミングのずらし・グリッサンドの置き場がない

本仕様では層を2つに分ける。

| フェンス | 役割 |
|---------|------|
| `phrase` | 音符そのもの。ASCIIグリッド (行=音高、列=時間) + 表情の詳細 |
| `loop`   | アレンジ。どのトラックにどのフレーズを載せるか |

### 設計原則

- **ASCIIのみ。** 罫線素片・ブロック文字・ブライユ文字は使わない。GitHubのファイルビューと
  エージェント (LLM) が壊れずに読み書きできることを優先する。装飾的な描画はレンダラの仕事。
- **編集操作を有限にする。** 任意の状態を表現できる記法を目指すのではなく、有限個の操作で
  到達できる状態だけを表現する (§7)。これにより往復の正しさが検証可能な性質になる (§8)。
- **導出できる情報はテキストに載せない。** 冗長な情報は手編集で嘘をつく。
- **記法は1つ。** 単音用の短縮記法は設けない。打楽器トラックは1行のグリッドになるため、
  一本化してもテキストは短いままである。

## 2. 用語

| 用語 | 定義 |
|------|------|
| フレーズ | `phrase` フェンス1つ。1トラック分の、1〜数小節のノート列 |
| 行 (row) | グリッドの1行。1つの音高、または1つの打楽器音源に対応 |
| セル (cell) | グリッドの1文字。時間の最小単位 |
| 始点 (onset) | ノートが発音するセル |
| グループ | 同じ始点にある、同じ記号のノートの集合。和音の単位 |
| アドレス | detail からノート/グループを指す座標 (§5) |
| ジェスチャ | detail に書く表情指定 (vel / nudge / gate / roll / gliss) |

## 3. `phrase` フェンス

```
```phrase id=verse-lead key=C scale=minor res=1/16 bars=1
grid:
  #     1...2...3...4...
  5'   |a---....o---....|
  b3'  |a---............|
  1    |b-------....o---|

detail:
  1.1a   : { roll: +12ms }
  1.1:1  : { vel: 90% }
```
```

### 3.1 フェンス属性

| 属性 | 必須 | 既定 | 内容 |
|------|------|------|------|
| `id` | ○ | — | フレーズ名。ドキュメント内で一意。`loop` から参照される |
| `key` | | `C` | 主音のピッチクラス (`C`, `F#`, `Eb` …) |
| `scale` | | `major` | `major` / `minor` / `dorian` / `phrygian` / `lydian` / `mixolydian` / `locrian` / `chromatic` |
| `res` | | `1/16` | グリッド解像度。1拍あたりのセル数を決める |
| `bars` | | `1` | 小節数 |

- `res=1/16` → 1拍4セル、`res=1/8` → 2セル、`res=1/12` → 3セル (8分3連)、`res=1/32` → 8セル
- 拍子は 4/4 固定 (可変拍子は次フェーズ、§11)
- 総セル数 = `bars × 4 × cellsPerBeat`。全行がこの長さに一致しなければエラー
- `key` / `scale` は将来フロントマター・セクションから継承する (§11)。現時点ではフェンス属性のみ

### 3.2 `grid:` セクション

`grid:` 以下、次のトップレベルキーまでが行の定義。

```
  <行ラベル>  |<セル列>|
```

- 行ラベルとセル列の間の空白は任意。フォーマッタは行ラベルを右揃えで桁揃えする
- セル列は `|` で開始し `|` で終了する。途中の `|` は小節線 (視覚用、パースでは無視)
- **小節線は全行で同じ桁になければエラー**
- `#` で始まる行はコメント。フォーマッタは先頭に拍のルーラをコメントとして生成する

#### 行ラベルの名前空間

ラベルの綴りで解決先が決まる。**1つのフレーズ内で名前空間を混在させることはできない。**

| 種別 | 綴り | 例 | 解決 |
|------|------|-----|------|
| 音度 | 数字、または小文字 `b`/`#` + 数字 | `1`, `b3`, `#4`, `5'`, `b7,` | `key`/`scale` から実音高を算出 |
| 絶対音高 | **大文字**の音名 + 任意の変化記号 + オクターブ | `C4`, `Eb2`, `F#5` | そのまま |
| 打楽器 | 上記以外の識別子 | `kick`, `sd`, `hh`, `oh` | キットマッピングで音高に解決 |

- **大文字小文字は有意。** `b3` は「短3度」、`B3` は「ロの3オクターブ」。曖昧さはこの規則で消える
- オクターブ記号 (音度のみ): `'` = 1オクターブ上、`,` = 1オクターブ下。複数可 (`1''`)
- `scale=chromatic` のときは音度 1〜12 が半音階に対応する
- 打楽器行のマッピングは当面 `synth` フェンス側の単音トラックに1対1で対応させる
  (キット定義は次フェーズ、§11)

#### 行の並び順 (正準形)

- 音度行・絶対音高行: **解決後の音高の高い順**
- 打楽器行: 著者が書いた順を保つ (自然な順序が存在しないため)
- 重複する行ラベルはエラー

### 3.3 セル記号

| 記号 | 意味 |
|------|------|
| `.` | 休符 |
| `-` | 直前のノートの持続 |
| `a`–`z` | 発音。文字はグループタグ (§3.4)。慣用的な既定は `o` |
| `\|` | 小節線 (視覚用) |

- ノート長 = 始点セル + 後続の `-` の数。ノートオフはセル末尾 - 1サンプル (既存仕様と同じ)
- 行頭の `-` (直前に始点がない持続) はエラー
- 打楽器行の `-` は許容されるが意味を持たない

### 3.4 グループ

> **同じ始点かつ同じ記号 = 1グループ。単独音は1人グループ。**

```
  5'   |a---....o---....|
  b3'  |a---............|
  1    |b-------....o---|
```

1拍目: グループ `a` = {5', b3'} (和音)、グループ `b` = {1} (独立)。3拍目: グループ `o` = {5'}。

- グループは **1つの始点の中に閉じる**。時間をまたぐグループは存在しない
  (モチーフの再利用はフレーズ参照とセクション継承の仕事)
- **グループはレンダリングに影響しない。** 音が変わるのは、グループを対象とする detail
  エントリが存在するときだけ (§8 不変条件3)
- 持続セル `-` と休符 `.` にタグは付かない

#### 正準化

1. ある始点の全ノートが1グループなら、記号は `o`
2. 2つ以上に分かれるなら、**上の行から** `a`, `b`, `c` … を順に割り当てる
3. タグは始点内でのみ意味を持つ。列をまたいだ一貫性は要求しない

この規則により、同じ構造からは必ず同じテキストが生成される。

## 4. `detail:` セクション

アドレス (§5) をキーとするフロー記法のマップ。省略可。

```
detail:
  1.1a     : { roll: +12ms }
  1.1:b3'  : { vel: 60% }
  *:1      : { vel: 80% }
  1.3      : { gliss: { to: +5st, cells: 3 } }
```

### 4.1 ジェスチャ

| キー | 値 | 対象 | 内容 |
|------|-----|------|------|
| `vel` | `0%`–`100%` | ノート | ベロシティ。既定 `100%` |
| `nudge` | `±Nms` | ノート | 発音タイミングのずらし |
| `gate` | `N%` | ノート | 記譜上の長さに対する実際の発音長。既定 `100%` |
| `roll` | `±Nms` | **グループのみ** | 構成音を順にずらす。`+` = 低音から、`-` = 高音から |
| `gliss` | 下記 | ノート / グループ | グリッサンド |

```
gliss: { to: <音度 | ±Nst>, cells: <整数>, curve: linear | exp }
```

- `to` が音度なら目標音へ、音程 (`+5st`) なら相対移動。**グループに適用した場合は全構成音が
  同じ音程だけ平行移動する** (構成音数の一致を要求しない)
- `cells` = 滑る時間 (セル数)。既定は始点から次の始点まで
- `curve` 既定 `linear`
- 目標に到達しないベンド (フォール / スクープ) は `to: -7st` のように音程で書く
- `gliss` を持つノートはレガート発音される (アンプエンベロープを再トリガしない)

### 4.2 単位

`docs/REQUIREMENTS.md` §3.1 の規約に従う。**裸の数値はエラー** (`cells` を除く)。

### 4.3 走句グリッサンド

音符が実在するグリッサンド (ハープ的な音階の駆け上がり) は detail ではなく grid に実音を並べる。
`scale` が効いているので、GUI の走句挿入操作が音度に沿った音を自動生成する (§7 `note.insertRun`)。

## 5. アドレスとカスケード

### 5.1 文法

```
<time>[<group>][:<row>]

time  := '*' | <bar> | <bar> '.' <beat> | <bar> '.' <beat> '.' <tick>
group := [a-z]
row   := 行ラベル
```

| 例 | 対象 |
|----|------|
| `1.1` | 1小節1拍の全ノート |
| `1.1a` | その中のグループ `a` のみ |
| `1.1:b3'` | 特定の1ノート |
| `1.1.3` | 1小節1拍の3ティック目 (1始まり) |
| `*:b3'` | `b3'` 行の全ノート |
| `1` | 1小節目の全ノート |
| `*` | フレーズ内の全ノート |

- `bar` / `beat` / `tick` はいずれも 1 始まり
- アドレスは **書かれた行ラベル** を指す。解決後の実音高ではない
  (`key` を変えて継承してもアドレスが壊れないため)

### 5.2 優先順位

各エントリの詳細度 = 制約の数。

```
詳細度 = (time の指定段数: * = 0, bar = 1, beat = 2, tick = 3)
       + (group 指定あり: +1)
       + (row 指定あり: +1)
```

詳細度が高いエントリが勝つ。同点なら **後に書かれたエントリが勝つ**。
ジェスチャのキー単位で解決する (あるエントリが `vel` だけを上書きしても `nudge` は残る)。

### 5.3 展開済みビュー

`docs/REQUIREMENTS.md` の「展開済みビュー」を phrase にも適用する。
各ノートについて、最終的な `vel` / `nudge` / `gate` / `gliss` と、**どのエントリが勝ったか** を
JSON で出力できること。カスケードがある以上、これが無いと値を追跡できない。

## 6. `loop` フェンス (アレンジ層)

```
```loop id=groove bars=1 bpm=126
lead: verse-lead
bass: verse-bass
kick: four-floor
hat:  offbeat
```
```

- 各行は `<トラックid>: <フレーズid>`。トラックid は `synth` フェンスの `id` に対応する
- トラックid は `synth` フェンスの出現順でトラックインデックス (0..7) に解決される (現行と同じ)
- **フレーズはループ長を埋めるまで繰り返される。** `bars`(loop) が `bars`(phrase) の倍数でなければエラー
- 未定義のフレーズid、未知のトラックid はエラー
- 1トラックに複数フレーズを順に並べる記法、セクション階層は次フェーズ (§11)

## 7. 操作セット

GUI・エージェントから到達できる編集操作はこの表が全てである。ここに無い状態はテキストにも現れない。

| 操作 | 引数 | テキストへの影響 |
|------|------|------------------|
| `note.add` | row, onset, length | 1行 / length文字 |
| `note.remove` | address | 1行 / length文字 → `.` |
| `note.movePitch` | address, newRow | 2行 |
| `note.moveTime` | address, newOnset | 1行 |
| `note.resize` | address, newLength | 1行 |
| `note.insertRun` | fromRow, toRow, onset, cells | 複数行 (scale に沿って生成) |
| `group.merge` | addresses (同一始点) | 1列のタグ文字 |
| `group.detach` | address | 1文字 |
| `row.add` | row label | 1行の挿入 |
| `row.remove` | row label | 1行の削除 (空行のみ) |
| `detail.set` | address, key, value | detail 1エントリ |
| `detail.clear` | address, key | detail 1エントリ |
| `phrase.transpose` | ±N (音度 or 半音) | 行ラベル群 |
| `phrase.setKey` | key, scale | フェンス属性 1トークン |
| `loop.bind` | track, phraseId | 1行 |

### 規約

1. **全操作は正準形を出力する。** 操作の結果は `format` を適用した状態と一致しなければならない
2. **全操作は全域的である。** 適用不能な入力に対しては、部分適用ではなく明示的な失敗を返す
3. **操作は対象スパン以外に触れない。** コメント・散文・他行は byte-for-byte で保存される
   (`web/src/dsl/edit.ts` の既存方針を踏襲)
4. `note.movePitch` / `note.moveTime` は、そのノートを指す detail エントリのアドレスも同時に更新する
5. 到達不能な状態の例 — 量子化されていない始点、行ラベルを持たないノート、
   1つの始点に同じ行が2つ

### エージェントAPI

この操作セットはそのままエージェント向けのAPIとする。LLM にテキストを丸ごと書き換えさせず、
検証済みの操作を呼ばせることで、§8 の不変条件が書き込み経路でも保たれる。

## 8. 不変条件と検証

| # | 不変条件 | 検証方法 |
|---|----------|----------|
| 1 | **可換性**: `parse(applyText(doc, op)) ≡ applyModel(parse(doc), op)` | ドキュメントと操作列を生成する性質テスト |
| 2 | **正準性の冪等**: `format(format(x)) == format(x)` | 同上 |
| 3 | **グループの音響的不活性**: 全タグを `o` に潰しても、グループを対象とする detail エントリが無い限り Loop IR は一致する | Loop IR の比較 |
| 4 | **局所性**: 任意の操作は対象スパン以外のバイトを変更しない | 差分の範囲を検査 |
| 5 | **決定性**: 同一ドキュメント + 同一シードでビット単位で同一出力 (既存要件から継続) | `dsp/tests/` |

1 は「GUIとテキストは同じものである」という本プロジェクトの中核の主張そのもの。
操作が有限であるためにこれが記述可能かつ検証可能になる。実装は `web/src/dsl/edit.test.ts` の延長に置く。

## 9. エラー仕様

エラー時は **直前の有効な状態で鳴り続ける** (Glicol方式、既存仕様から継続)。
エラーは `{ line, col, message }` で返し、ドキュメント絶対座標を用いる。

| 分類 | 条件 |
|------|------|
| グリッド | 行長が `bars × 4 × cellsPerBeat` と不一致 |
| | 小節線 `\|` の桁が行間で不一致 |
| | 行頭の `-` (始点のない持続) |
| | 行ラベルの重複 |
| | 名前空間の混在 (音度行と打楽器行の同居) |
| | 未知の行ラベル |
| アドレス | 存在しないノート/グループを指す (**孤児アドレス。黙って無視しない**) |
| | 構文不正 |
| ジェスチャ | `roll` をグループ以外に適用 |
| | 単位なしの裸の数値 |
| loop | 未定義のフレーズid / 未知のトラックid |
| | `bars`(loop) が `bars`(phrase) の倍数でない |
| フェンス | `id` の重複 / 欠落 |

## 10. DSPコアへの影響

`gliss` の実現には、ノートイベント単位のグライド時間とレガート指定が必要になる。
現行 ABI (`docs/SPEC.md` §2):

```
note_on(track: u32, note: f32, velocity: f32)
```

を次のように拡張する。

```
note_on(track: u32, note: f32, velocity: f32, glide_s: f32, legato: u32)
```

- `glide_s < 0` — パッチの `voice.glide` を使う (従来の挙動)
- `legato != 0` — アンプエンベロープを再トリガしない。グリッサンドの途中で音が切れるのを防ぐ
- パラメータブロックのレイアウト (`dsp/src/params.rs` / `web/src/shared/params.ts`) は変更しない

`nudge` / `roll` / `gate` は TS 側で Loop IR のオフセットに畳み込むため、DSP の変更は不要。
グリッサンドのカーブ (`curve: exp`) も TS 側でグライド時間に写像する範囲に留め、
汎用のピッチオートメーション (ノート単位の任意カーブ) は導入しない。

## 11. 次フェーズに送るもの

本仕様では扱わない。ただし記法が将来これらと衝突しないことを確認済み。

- **フロントマター** — 曲ヘッダ (title / bpm / key / scale / tempo map / engine version)。
  `key` / `scale` はフロントマター → セクション → フェンスの順に継承する
- **セクション階層** — 見出しをアレンジの区間とし、文書順を再生順とする。`from=` による継承と上書き
- **階層オートメーション** — energy / density などの抽象カーブを階層ごとに定義して合成する
- **可変拍子・テンポマップ** — 現状 4/4 固定
- **キット定義** — 打楽器行ラベルのマッピングを明示的に宣言する
- **フレーズの連結** — 1トラックに複数フレーズを順に並べる記法
- **MIDI相互運用** — グループの概念が無いためインポートは全ノートが1人グループになる。
  §8 不変条件3 により、グループが落ちても音は変わらない
- **入力糖衣** — 手打ち用の1行トークン記法。保存時にグリッドへ正規化する。
  **第2の保存形式にはしない**
