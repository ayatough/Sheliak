# Wavetable WASM Synth — MVP 要件定義

> Markdownベース作曲システムの第一歩として、シンセの音作り層のみを切り出したMVP。
> format_version: 0.1

---

## 1. ゴールと非ゴール

### ゴール（MVPの完了条件）

1. `.md` 内のコードフェンスに書いたシンセDSLを解釈し、ブラウザで**音が鳴る**
2. 短いループ（1〜4小節）を**サンプル精度で繰り返し再生**でき、音色作りの試行錯誤ができる
3. DSLを編集して即座に反映される（**ホットリロード**、再生を止めずに）
4. 同じDSL＋同じシードから**常にビット単位で同じ音**が出る（決定性）
5. スマホのブラウザ（iOS Safari / Android Chrome）で実用的な音数が出る

### 非ゴール（MVPでは作らない）

- 曲構成・アレンジ層、複数トラック、ミキサー
- エフェクト全般（フィルタとドライブ以外）— OTT・リミッタ・リバーブ等は次フェーズ
- サンプラー、ユーザーサンプルの読み込み
- ノブ・スライダーのGUI（テキスト編集のみ）
- オーディオ書き出し、ネイティブ（AUv3/VST）エクスポート
- 自然言語→DSL変換（AIによる生成は後付けで足りる）

## 2. アーキテクチャ

```
[ Markdownエディタ (TS) ]
        │  コードフェンス抽出
        ▼
[ DSLパーサ (TS) ]  ── 構文エラー・単位検証・展開
        │  正規化された Patch IR (JSON)
        ▼  postMessage
[ AudioWorkletProcessor (TS薄いグルー) ]
        │  Patch IR を WASM に流し込む
        ▼
[ DSPコア (Rust → wasm32) ]  ── 音声生成のみ。DSLを知らない
        │
        ▼  Float32Array (L/R)
    出力バッファ
```

### 設計原則

- **DSPコアはDSLを一切知らない。** WASM側の入力は「正規化済みのフラットなパラメータ構造体」のみ。これにより DSL は自由に変えられ、DSPコアは後からネイティブ（AUv3/VST）に流用できる。
- **パーサはTS側（メインスレッド）。** MVPの反復速度を優先。Rust側に持つとホットリロードのたびにWASM再ビルドが必要になり開発が遅い。将来ネイティブ移植時にRustへ移す前提で、パーサの出力形式（Patch IR）を先に安定させる。
- **`process()` 内でアロケーションしない。** ボイス・バッファ・ウェーブテーブルは全て事前確保。

## 3. DSL v0 仕様

### 3.1 共通レキシカル規約（全記法で共有）

| 種別 | 表記 | 例 |
|------|------|-----|
| 周波数 | `Hz` / `kHz` | `320Hz`, `4.5kHz` |
| ゲイン | `dB` | `-6dB` |
| 時間（絶対） | `ms` / `s` | `180ms` |
| 時間（音楽的） | `1/16`, `2bar`, `1.5beat` | `1/8` |
| ピッチ | `c`(cent) / `st`(semitone) | `-7c`, `+12st` |
| 比率 | `%` または 0.0–1.0 | `70%` |
| 参照 | ドット記法 | `filter.cutoff` |

**裸の数値はパースエラーにする**（0.0–1.0 の正規化値を明示的に許可するフィールドを除く）。単位の取り違えを型レベルで潰す。

### 3.2 パッチ記法

````markdown
```synth id=lead
osc:
  - { table: basic/saw, level: 0dB, morph: 0%, unison: 7, detune: 22c, spread: 80% }
  - { table: basic/square, level: -8dB, morph: 30%, tune: -12st }

filter: { type: lp12, cutoff: 800Hz, res: 0.3, drive: 0.2, key_track: 50% }

env:
  amp:    { a: 5ms,  d: 200ms, s: 70%,  r: 120ms }
  filter: { a: 2ms,  d: 400ms, s: 0%,   r: 100ms }

lfo:
  1: { wave: tri, rate: 1/4, phase: 0% }

mod:
  - { from: env.filter, to: filter.cutoff, amount: +2400c }
  - { from: lfo.1,      to: osc.1.morph,   amount: 25% }

voice: { polyphony: 8, glide: 0ms }
```
````

### 3.3 ループ記法（MVP最小版）

````markdown
```loop id=demo bars=2 bpm=124
lead: C3 . Eb3 . | G3 ~ ~ . | Bb3 . . . | C4 ~ ~ ~
```
````

- `.` = 休符、`~` = 前のノートを伸ばす、`|` = 拍の区切り（1拍＝1セル群）
- MVPは単音・固定ベロシティで可。和音は `[C3 Eb3 G3]` で後付け
- **ループは常にループする**（ワンショット再生はMVP不要）

### 3.4 パーサ要件

- コードフェンスの info string（`synth id=lead`）をキー＝値でパース
- 中身は YAML サブセット（フロー記法 `{}` `[]` を主に使う）
- **エラーは行番号・列番号付きで返す**。エラー時は**直前の有効なパッチで鳴り続ける**（Glicol方式）
- 未指定フィールドはデフォルト値で補完し、「展開済みビュー」として全値を出力できること（透明性のため）

## 4. DSPコア要件（Rust / WASM）

### 4.1 ウェーブテーブルエンジン

| 項目 | 仕様 | 備考 |
|------|------|------|
| フレーム長 | 2048 samples | 業界標準。Serum/Vital互換 |
| フレーム数 | 1〜256 | モーフ対象 |
| 位相アキュムレータ | `u32` 固定小数点 | f32だと高域で位相精度が落ちる |
| サンプル間補間 | Hermite (4点3次) | 線形だと高域で歪む |
| フレーム間補間 | 線形 | モーフ位置 |

**バンドリミット（最重要）**
- ロード時にFFTで**オクターブごとのミップマップ**を生成（ナイキストを超える倍音を除去）
- 再生時は基本周波数からミップレベルを選択、レベル間はクロスフェード
- ここを手抜きするとエイリアスノイズで「安っぽい音」になり、MVPの意味が消える

**ユニゾン**
- 最大7ボイス
- デチューン曲線は **JP-8000型の非線形カーブ**（Adam Szaboの多項式近似）を実装。線形にするとSupersawらしくならない
- ステレオ拡散：ボイスごとのパン配置
- 初期位相：**シード付き乱数**（`seed` はパッチ単位、未指定なら 0）

### 4.2 ボイスアーキテクチャ

- 最大ポリフォニー：16（デフォルト8）
- ボイスあたり：ウェーブテーブルOSC ×2 → ミックス → フィルタ → アンプ
- **フィルタ**：TPT/ZDF ステートバリアブルフィルタ（Zavalishin方式）
  - モード：`lp12` / `lp24` / `hp12` / `bp12`
  - カットオフをオーディオレートで動かしても安定するのでモジュレーション向き
  - ドライブ（tanhソフトサチュレーション）を内蔵、**2倍オーバーサンプリング**
- エンベロープ：ADSR ×2（amp / filter）、指数カーブ
- LFO ×1（テンポ同期、フリーラン両対応）
- モジュレーションマトリクス：最大8スロット（線形リスト。行列である必要はない）

### 4.3 ボイススティール

ポリフォニー超過時は「最も古いリリース中のボイス」→「最も古いボイス」の順で奪う。奪う際は**1〜2msの高速フェードアウト**を挟む（クリック防止）。

### 4.4 パラメータ更新

- メインスレッド → Worklet はロックフリーのリングバッファまたは `postMessage`（MVPは後者で可）
- **全パラメータを1サンプルブロック内で平滑化**（one-pole smoother, ~5ms）。生の値を直接代入するとザッパーノイズが出る
- カットオフ・ピッチは**対数領域で平滑化**する

## 5. Web層要件

### 5.1 AudioWorklet まわりの必須事項

- WASMのコンパイルは**メインスレッドで行い、`WebAssembly.Module` を postMessage で Worklet に転送**する（Worklet内で fetch はできない）
- `AudioContext` の生成・`resume()` は**ユーザージェスチャ内**で行う（iOSは特に厳格）
- **サンプルレートをハードコードしない**。44.1k / 48k どちらも来る
- 処理単位は 128 frames（AudioWorkletのレンダークォンタム）
- **MVPではWASMスレッドを使わない**（SharedArrayBuffer は COOP/COEP ヘッダが必要で、デプロイが複雑化する）。シングルスレッドで性能目標に届くか先に確認する

### 5.2 スケジューリング

- **`setTimeout` / `setInterval` でノートを鳴らさない。** ループの再生位置はWorklet内のサンプルカウンタで管理し、ノートオン/オフをサンプルオフセット付きイベントとして処理する
- ループ長・BPMの変更は次のループ境界で反映（MVPは即時反映でも可）

### 5.3 UI（最小限）

- テキストエリア（またはCodeMirror）＋ 再生/停止ボタン ＋ エラー表示
- 「展開済みパラメータ」の折りたたみ表示
- 波形またはスペクトラムの簡易表示（`AnalyserNode` で十分、任意）

## 6. 性能目標

| 環境 | 目標 |
|------|------|
| デスクトップ Chrome | 16ボイス × 7ユニゾン × 2OSC = 224オシレータで CPU < 30% |
| iPhone (直近3世代) Safari | 8ボイス × 7ユニゾン で グリッチなし |
| Android ミドルレンジ Chrome | 8ボイス × 5ユニゾン で グリッチなし |

- WASM SIMD を有効化（`-C target-feature=+simd128`）。ユニゾンボイスのSIMD化が最も効く
- レイテンシは Web の制約上 20–50ms 程度になる。MVPでは許容（リアルタイム演奏ではなくループ再生が用途のため）

---

## 7. 決定性の要件

1. **乱数は全てシード付き**（xorshift または PCG）。初期位相、ユニゾンのばらつき、ノイズが対象
2. 同一DSL＋同一シード＋同一サンプルレート → **ビット単位で同一の出力**
3. 浮動小数点：SIMD有無で結果が変わる可能性がある。**MVPでは「同一ビルド内での再現性」まで**を保証し、ビルド間のビット一致は求めない（後で必要になったら検討）
4. 検証：同じパッチを2回オフラインレンダリングし、差分がゼロであることをテストする

## 8. 実装フェーズ

### Phase 1 — 音が出る（土台）
Rust WASM ↔ AudioWorklet の配線。固定周波数のサイン波を鳴らすだけ。ここでビルドパイプライン・postMessage・iOS動作を潰しておく。

### Phase 2 — ウェーブテーブルOSC
テーブルロード、ミップマップ生成、Hermite補間、モーフ。**エイリアステスト**（高音域のスイープでスペクトラムに不要な成分が出ないか）をここで必ず通す。

### Phase 3 — ボイス
ADSR、SVFフィルタ、ポリフォニー、ボイススティール、パラメータ平滑化。

### Phase 4 — ユニゾン / Supersaw
JP-8000デチューンカーブ、ステレオ拡散、シード付き位相。**MVPの音のキモ**。

### Phase 5 — DSLパーサ
コードフェンス抽出、単位パース、デフォルト補完、エラー表示、ホットリロード。

### Phase 6 — ループ再生
サンプル精度スケジューラ、ループ記法パーサ。

### Phase 7 — 仕上げ
モジュレーションマトリクス、LFO、性能チューニング（SIMD）、スマホ実機確認。

> Phase 1〜4 で「音の質」が決まり、Phase 5〜6 で「体験」が決まる。Phase 4 が終わった時点で一度、手打ちのJSONで Supersaw を鳴らして音質を評価するのを推奨。

## 9. 検証方法

- **エイリアステスト**: OSCをC1→C8までスイープさせオフラインレンダリング → スペクトラムに倍音以外のピークが -60dB 以下
- **決定性テスト**: 同一パッチの2回レンダリングでヌルテスト（差分 = 完全な無音）
- **クリックテスト**: ノートオン/オフ、パラメータ急変、ボイススティール時に不連続がないか波形で確認
- **性能テスト**: 実機で最大ボイス数を鳴らし、`AudioContext` の underrun カウントを監視
- **DC/レベルテスト**: 出力にDCオフセットがないこと、クリップしていないこと

## 10. 技術選定

| 領域 | 選択 | 理由 |
|------|------|------|
| DSP言語 | **Rust** | ネイティブ移植・SIMD・安全性。将来Faust/Cmajorのモジュールを部分的に取り込む余地も残す |
| ビルド | `wasm-bindgen` は使わず、`wasm32-unknown-unknown` の raw export | Workletでのグルーが軽くなる。バッファはWASMメモリの生ポインタで受け渡し |
| パーサ | TypeScript（YAMLサブセットを自前パース） | 反復速度優先。将来Rustへ移す |
| FFT（テーブル生成時のみ） | `rustfft` | リアルタイムパスでは使わない |
| フロント | Vite + TS（フレームワークは任意） | AudioWorkletのバンドルに癖があるので設定に注意 |

---

## 11. 保留・要判断事項

1. **ウェーブテーブルの入手元** — 自前生成（saw/square/tri等の基本波形＋数種のモーフテーブル）でMVPは十分か、既存のwtファイル（Serum形式）を読むか。ライセンス的には自前生成が安全
2. **`.wt` ファイル形式のサポート** — MVPでは不要と判断したが、音色の幅を早く得たいなら Phase 2 に前倒しする選択肢あり
3. **オフラインレンダリング機能** — 検証には必須だが、ユーザー向け機能としてはMVP範囲外。テスト用に内部APIとして先に作るのが効率的
4. **フィルタの種類** — `lp12/lp24` だけでMVPは足りるか。EDM的にはコムフィルタやフォルマントも欲しくなるが後回しでよい
5. **ノイズオシレータ** — ライザー系に必須だが、MVPのスコープには入れていない
